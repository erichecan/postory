【响应式】
- 桌面以指定视口为视觉验收基准，不强行让不同原图比例使用同一固定宽度。
- 移动端默认规则（暂无独立移动稿）：375/390 px，左右边距 16 px；大屏到小屏保持原有内容顺序。
- 公开页 Hero 从双列变单列：文案、CTA、主视觉；卡片按原阅读顺序排列，多列降为单列或可容纳的两列。
- 顶部导航折叠为菜单，保留 Logo 与主要入口；菜单支持键盘、Escape 关闭和焦点返回。
- 客户区侧边补充信息移至主内容之后；不缩小整张桌面布局来假装移动端。
- 日历在窄屏提供日期切换与列表/日程视图；若保留周/月网格，滚动限于日历内部，页面不能整体横向滚动。
- 控件点击区域尽量不小于 44 px；检查中间宽度的标题换行、图片裁切和网格溢出。

【交互】
导航：公开页链接到上表路由；Logo 在公开网站返回 /，客户区可返回 /dashboard。客户顶部导航链接到 Dashboard、My Campaign、Marketing Calendar、My Brand；活动卡片链接到对应活动详情，不能使用无行为的占位链接。
主按钮：公开页免费评估 CTA 进入 /assessment；案例入口进入对应 Demo；客户区按钮按参考文案映射到查看内容、筛选、更新品牌资料或现有授权动作。
Assessment 表单：先按图片确认实际字段。推荐实现基线为联系人姓名、邮箱、商家名称、行业、网站/社媒链接和业务目标；图片未显示的字段不得擅自新增为必填。验证必填项、邮箱格式、链接格式与合理长度，保留输入、显示字段错误、提交中状态及成功反馈。复用真实服务端提交链路；若没有链路，明确说明未提交，不伪造成功。
客户区：活动状态、内容排期、平台状态和统计数据复用现有数据模型与权限。审批、修改建议置于活动详情/内容详情；不额外建立审批一级入口。不能把图中的演示数据当作已接通的社媒实时数据。
My Brand：资料编辑与保存复用现有能力；品牌资料表单本身不要求接 OpenAI API。
Calendar：支持日期/月份切换、查看活动及内容详情、平台或状态筛选（以最新版图中实际控件为准）。保留彩色日历的层级与图例。
悬停、键盘焦点、禁用、加载、空数据与错误状态保持整体视觉一致。键盘可操作表单、菜单、标签页和弹层；社媒连接、邮件、发布或数据采集按现有集成的真实能力处理，不以视觉开发名义发送真实营销内容。
