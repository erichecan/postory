# PoStory 设计与文案质量标准 v1

日期：2026-11-21。适用：寿司首个行业样板；逐步扩展其他线下门店。定位：**Done-for-You 营销服务，不是给店主出售的自助设计 SaaS**。

## 设计标杆与版权边界

参考方法而不是复制第三方作品：Sora Omakase（制作过程、体验感、少量文案）、Sukiyaki House（单品、克制版式、活动事实）、Yakumi（产品组合/季节主题）、SUSHIRO（近景食物与手机端识别）。案例仅作研究；不使用其商标、摄影和设计源文件制作 PoStory 商用模板。可在设计审核时对照 Adobe 强调的视觉层级、留白、一致性与移动端可读性。餐厅广告须同时考虑 OpenTable 风格的清晰行动入口。

## 六道强制质量门槛

1. **视觉主体**：手机上一眼能看到被推广的具体菜品、服务或真实体验。无菜品资料时不能凭空生成一道“该店的菜”。
2. **信息层级**：真实主视觉 → 一句明确的场景/菜品/实际优惠 → 必要的条件和一个 CTA；避免多重文字竞争，不以华丽背景掩盖商品。
3. **品牌识别**：店名、Logo、色板、语气统一；跨帖子版式、景别和素材应有节奏变化，不能每张都是同一黑金海报。
4. **真实可信**：使用有授权的真实食物/门店/员工素材；不虚构配料、份量、优惠、供应日期、认证、评论、销量或结果。插画和概念示意必须标明，不能冒充实际菜品。
5. **营销关联**：图片主题、图片标题、社媒正文、活动规则和 CTA 必须针对同一个经营目标。
6. **手机可读性**：用手机 Feed 尺寸人工验收标题/日期/价格；文案优先简短、留白、重要文字不贴边，不能有遮挡和断字。

## 内容格式，不是每帖都做海报

- **real_photo**：授权的真实食物/制作过程/门店实拍，尽量不加字；高端定位和可信度。
- **brand_editorial**：真实素材加极简标题/品牌落款；主推单品、主厨故事、预约体验。
- **offer_poster**：只有已核实的商品、时段、价格、资格、限制时使用；时间、价格与完整规则必须统一。
- **carousel**：知识/菜单选择/真实套餐组合等多张图；逐页一重点、尺寸统一、避免伪造套餐或营养结论。

模板选择应由实际素材、营销目标和客户品牌决定，而非一律输出“高级黑金”。不满足实拍条件时请求补图，不能拿 AI 猜测图充当真实菜品照片。视觉可以表达设计概念，但不能被当作门店经营事实。

## 三层文案严格分离

1. **imageHeadline（图片短标题）**：通常一句话，强调具体菜品或客户场景；不要堆在图片上。没有必要时允许空白标题，使用实拍即可。
2. **socialCopy（平台正文）**：从顾客场景切入，补充客户已确认的菜品/服务事实、实际位置或营业时段，并在末尾放**一个可执行 CTA**。按 Facebook、Instagram、TikTok、小红书分别适配，不得捏造第一人称体验。
3. **promotionTerms（完整活动规则）**：只有真实优惠/活动经过确认后才生成。包含适用商品、开始结束、时区、参与渠道、资格、门槛、限制和真实价格等适用事实；未确认则留空并标记“待确认”，不进入正式发布。

### 不合格与修订

- 不合格：“Enjoy delicious sushi today!”、“Your lunch break, made better.”，没有具体寿司或场景。
- 更好：“Short on lunch time? Make it a sushi lunch.”，但仍必须由该店真实供应的菜品、地址/营业时间和 CTA 支撑。
- 不得把“请店主填价格”“以门店实际为准”等内部制作备注伪装成已经可发布的营销事实。信息不足应让 PoStory 运营端提出**待核实项**，不将其偷塞进广告。
- 没有真实促销不生成折扣/优惠码/倒计时。永不承诺带来一定客流。

## 交付与验收

PoStory 内部：确认经营目标 → 收集真实素材/门店事实 → 选择格式与模板 → 审核三层文案和真实性 → 生成 1:1/4:5/9:16 → 手机 Feed 检查 → 店主集中审核 → PoStory 排期、发布、复盘。客户的主要体验是**交素材、确认品牌与内容**，不是买一个设计工具自行制作。

审核人在发布前逐条检查：主体是否明确；事实是否能从来源证实；视觉与标题是否对准一个目标；品牌与手机阅读；是否有明确 CTA；活动规则是否完整并确认；是否有客户授权。**任何一项不合格必须修订，不能自动批准。**

## 工程实现提示

- 生成接口严格区分：headline（图上短标题）、copy（社媒正文）、callToAction、promotionTerms（完整规则）、contentFormat（内容形式）、visualDirection（制作说明）。
- 图片生成与排版分开：商品实拍是默认，图片模型不可自行创造未确认菜品/食品细节；完整促销规则不能直接绘制到图片上。
- 兼容历史的营销日历数据和非寿司行业。新增字段可选并提供安全默认值，保留旧的流程。
- 用真实预览与最终渲染接受人工手机端测试；单纯代码测试不能证明视觉品质。
