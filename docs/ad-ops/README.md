# PoStory Ads Studio · 代运营流程原型

> 本 README 最初描述静态可点击原型。PoStory 应用内的数据库驱动 Ads Studio 已实现到客户配置、任务、审批、模拟和手工报告阶段，见 [功能实现状态](./implementation-status.md)。

本目录交付一套以模拟数据演示的多客户广告代运营流程：先定义流程，再用可点击的界面走完授权、策划、审批、模拟投放、报告和客户查看。它是 PoStory 仓库内的独立静态原型，不接入生产路由、数据库或广告平台。

## 快速运行

在 PoStory 仓库根目录运行：

```sh
python3 -m http.server 4173 --directory docs/ad-ops/prototype
```

打开 `http://localhost:4173`。项目运行不需要依赖安装、环境变量、广告凭据或数据库。演示数据保存在当前浏览器的 `localStorage`；点击侧栏底部「重置演示」可恢复初始流程。

## 推荐演示路径（爱尔兰餐厅场景）

1. 首页以 Harbour Table（Dublin 2）为例展示一项完整优惠任务：周一至周四双人晚餐，客户授权每日 €20、7 天总额 €140。
2. 查看首页五步流程，区分客户确认、运营建任务、系统自动预检/巡检和仅异常审批。
3. 点击「新建推广任务」，选择优惠、日期和顾客行动；系统继承客户已确认的区域、预算和 Meta 账户，并推荐宽泛的本地受众。受众选项供运营人员微调，客户不用填写年龄或兴趣标签。
4. 在素材步骤选择 PoStory 日历素材，查看 ChatGPT 优化后的文案；文案由运营人员检查，不要求客户撰写。优惠价格或限制不清楚时先向客户核实。
5. 查看审批中心：只有新优惠、预算/渠道变更、授权异常等越界事项需要人工处理；原型动作只更改本地模拟状态。
6. 在报告查看广告花费、领券、预约和到店核销；报告明确预约不等于到店，核销/POS 数据尚未接入时会显示待回传。
7. 从客户入口预览查看该客户可见的预算边界、推广任务和经营结果。

所有数据、授权、审批和投放均为本地演示，不会访问真实广告平台或产生费用。演示状态保存在浏览器 `localStorage`；侧栏「重置演示」可恢复初始内容。

## 开源仓库拉取与运行审计

克隆副本位于 `repositories/`，均来自公开 GitHub 仓库的浅克隆。审计时锁定的提交和逐项运行结果见 [开源仓库审计](./repository-audit.md)。没有向仓库写入任何账号、访问令牌或广告预算。真实平台授权和生产部署需要单独完成各平台审核、域名/OAuth、安全密钥与客户授权流程；本轮不启用。
