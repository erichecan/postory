+# Ads Studio · 功能实现状态

Ads Studio 已从静态演示扩展为 PoStory 内需要登录的数据库驱动流程，覆盖爱尔兰本地商家的客户配置、推广任务、越界审批、模拟状态和人工结果回报。金额以欧分保存，时区固定为 Europe/Dublin。客户不填写营销文案或人群标签：运营人员负责优惠与文案，系统根据客户确认的经营区域给出宽泛本地受众建议。

## 本地使用

1. 启动 PoStory 的 PostgreSQL 数据库，并确认项目本地环境变量已配置。
2. 在仓库根目录运行 `npx prisma migrate deploy` 和 `npm run dev`。
3. 登录后打开 `/ad-ops`。客户从 `/ad-ops/portal` 确认经营目标、预算上限、服务区域、允许渠道/优惠和规则内自动执行许可。
4. 运营人员从客户页建立任务，选择 PoStory 已有设计素材，补充优化后的优惠文案、落地去向和日期；系统自动检查授权边界并创建审批或预检阻断。
5. 当前任务页的“模拟运行/暂停”只更新本地状态，不调用广告平台、不消耗预算。结果由客户或运营人员手动录入，来源会标记为 MANUAL。

启动命令示例：

```sh
npm run dev
```

## 已实现

- 客户隔离通过现有 AgencyAccess 关系执行；客户只能确认自己的配置和查看自己的任务。运营人员也只能访问已关联客户。
- 客户配置具有显式确认状态。运营人员修改边界后会清除确认和规则内自动执行授权，要求客户重新确认。
- 任务读取确认后的目标/区域；按每日与月预算、渠道和优惠白名单进行预检。新渠道、新优惠、超预算等情形进入客户异常审批。
- 使用客户自己的 PoStory Design 素材；任务保留创意来源、落地方式、优惠详情和投放期间快照。
- 有版本号、审批记录和审计事件；客户要求修改后，运营人员可以更新并提交新版本。
- 手工回报花费、点击、领券、预约、核销及销售额，并可供客户入口查看。
- 新增数据库迁移：`prisma/migrations/20261028120000_ad_ops_foundation/migration.sql`。

## 当前边界

- 付费广告账户和平台 OAuth 尚未接入；表结构不会复用 PoStory 的自然内容发布账号，也不存平台令牌。没有授权账户会显示预检阻断。
- 因此当前不能实际创建/更新广告系列、自动优化或自动同步 Meta/Google 等平台数据。所有“运行”入口明确是无花费模拟。
- 要接通真实平台，需要分别配置并审核平台应用、OAuth 回调域名与权限，完成客户资产授权，然后实现平台适配器、令牌加密存储/轮换、webhook 或周期同步、限额保护和可审计的真实投放开关。现有界面不会把这一步伪装成已完成。
- 报告数据目前来自人工录入；领券/预约/核销的真实转化归因、POS/预订系统同步与客户短信营销合规流程仍需单独接入。

## 数据库

本地开发数据库迁移已应用；新环境请按项目流程配置数据库后执行 `npx prisma migrate deploy`。数据库字段与读取路径实现了应用层客户隔离。生产上线前仍需做数据库级访问策略、角色与审计保留策略评审，并进行平台合规审查。
