# PoStory 行业专属入口与营销规则架构 v1

日期：2026-11-21。实施范围：阶段 1（行业入口）和阶段 2（可复用规则引擎），保持已有 `/store` 五步框架与 Sakura Sushi 广告素材不变。

## 产品边界

PoStory 永远定位为 **Done-for-You 线下门店营销代运营服务**，不是出售给店主每天自己操作的 SaaS 设计软件。地推人员按行业发送链接；每位老板只看到本行业的经营目标、内容案例与适用的营销机制，不显示行业选择器。

- `/for/sushi` 寿司餐饮
- `/for/nails` 美甲美容
- `/for/roofing` 屋顶装修
- `/for/accounting` 会计报税
- `/for/fitness` 健身
- `/for/retail` 零售家具

**行业链接是公开营销体验入口，不是客户身份或租户授权凭证。** 同一行业的多个客户仍必须在未来的 Brand Profile 持久化环节做严格的店铺级权限隔离。行业 slug 不授权读取其他用户数据。

## 两种界面

**客户侧：** 专属行业营销目标和案例 → 提交门店经营资料与真实素材 → 了解合适的促销机制 → 形成营销需求预览 → 联系 PoStory，由运营团队继续对接。

**PoStory 内部：** 行业目标/文案/促销规则 → 素材审核与生成 → 集中审核 → 正式批准 → 排期发布 → 月报。现有 `/store` 为兼容旧版的演示/操作页面，新的行业路径不将其内容制作日历暴露给店主。

本次尚**未实现**线上自动保存 Brand Profile、自动创建服务订单或真正的客服提交记录。为避免误导，客户最后一页明确显示“本地预览，未正式提交”，引导至现有的咨询/评估入口。真实的上传持久化、Brand Profile 后端与受控编辑权限属于下一阶段。

## 规则结构

`src/lib/verticals/config.ts` 是单一来源，包括：

- `VerticalConfig.goals`：行业内 5–7 个优先目标，目标包含底层通用营销类别、独立的消费者场景、不同的视觉构图说明和效果观察项。
- `VerticalConfig.promotions`：行业适合的具体活动机制、必须核实的经营事实、禁止的夸大和虚假表达。
- `VerticalConfig.copyRules / imageRules`：行业说服结构、真实素材要求和 CTA。
- `VerticalConfig.intake`：每个行业的名称、商品或服务、照片资料等表单文案。
- `vertical.slug`：从 URL 确定，客户界面不允许切换。

已启用服务端生成 API 的可选垂直参数校验：`verticalSlug`、`goalId`、`promotionId` 和 `verifiedPromotionFacts`。采用行业配置时服务端严格校验行业、目标和活动类型匹配、以及必须核实的活动字段，不完整直接拒绝，不让模型捏造优惠。真实证据仍需运营团队核验；勾选确认不等同于独立事实认证。

## 素材与客户可信度

寿司行业使用现有 Sakura Sushi 的七张正式广告概念作品；美甲行业使用仓库中的真实风格演示照片（并不声称客户真实成果）。屋顶、会计、健身和零售当前使用**明确标注的行业创意方向卡片**，没有在阶段 1/2 偷换成虚构施工项目、会计资格证书、健身会员或商品照片。后续阶段 3 应为每行业建立独立的、可核验权利和事实的高质量图片案例库。

## 发布与版本

`/store` 保持旧版兼容。`/for/[industry]` 由同一五步组件驱动，稿件使用 `postory-industry-brief-v1-${slug}` 隔离浏览器缓存。未知行业 URL 404，公开路由无需登录，后台和正式客户数据访问控制不改变。

## 验收标准

1. 六个链接均可在无账户时打开，直接看到对应的行业目标，没有行业切换器。
2. 寿司原 7 目标、原侧栏和五步框架不发生视觉回退。
3. 屋顶不出现寿司营销文案；会计不出现食品折扣；各行业促销机制和事实校验各不相同。
4. 进入第二步行业不可变，表单标题和示例符合链接所属行业。
5. 客户完成五步后不进入内部社媒内容设计编辑器；页面不得宣称 Brand Profile 已提交或正式建档。
6. 未经核实的促销规则无法继续，或进入通用生成接口。
7. CI 检查配置、路由、隔离、真实图像渲染和生产构建。
