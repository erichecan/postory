## 1. 项目背景与目标

用户是一名代理商/个人运营者,计划做一个面向"品牌资料不完整的小微商家"的社媒代运营 SaaS:

- 商家客户提供:店名、Logo、少量文案要点/照片
- 商家客户从运营方预先筛选好的模板库里**选一个模板**(不能编辑模板设计本身)
- 系统自动:AI 写文案 → 调用 Orshot 用商家的 Logo/文字渲染出成品图 → 通过 Ayrshare 发布/排期到商家已连接的真实社交账号(Instagram/Facebook/LinkedIn/TikTok/…)
- 运营方在后台统一管理所有商家客户、模板库、用量成本

这是一个"新模块"级别的全新项目(不是在已有项目上加功能),按第十一节走 DEV-PLAN 全流程。

## 3. 模块拆解

| 模块 | 说明 |
|---|---|
| M1 认证与账号 | 运营方(Admin)账号 + 商家客户(Client)账号,两套角色 |
| M2 商家客户档案 | 店名、Logo、品牌关键词、联系方式的增删改查 |
| M3 社交渠道连接 | 调 Ayrshare `connect-link` 生成授权链接,商家自助 OAuth 连接,状态回读 |
| M4 模板库(运营方维护) | 从 Orshot 模板库挑选/导入模板,打标签(行业/风格),定义每个模板暴露给前端的字段 |
| M5 内容提交(商家客户用) | 商家选模板、填字段/写一段话简介、可选上传照片 |
| M6 AI 文案生成 | 调 LLM 把商家的简介 + 品牌关键词 → 生成 caption + hashtag |
| M7 图片/视频生成 | 调 Orshot `render` 接口,把商家 Logo/文案/照片套进选定模板 |
| M8 预览与审核 | 生成结果展示给商家(或运营方)确认后才进入发布队列 |
| M9 排期与发布 | 调 Ayrshare `schedule`/`publish`,指定目标平台与时间 |
| M10 历史与状态跟踪 | 商家可查看自己每条内容的状态(草稿/生成中/待审/已排期/已发布/失败) |
| M11 运营后台:客户与用量管理 | 查看每个商家消耗了多少 Orshot credit、连了几个 Ayrshare profile,人工设额度上限 |
| M12 异步任务处理器 | 定时轮询"生成中/待发布"状态的任务,推进流水线、处理超时与重试 |
| M13 审计日志 | 记录谁在什么时候做了什么关键操作(连接渠道、发布、删除) |

## 4. Schema 设计(Prisma,概要)

```prisma
model AdminUser {
  id        String   @id @default(cuid())
  email     String   @unique
  passwordHash String
  role      AdminRole @default(STAFF)
  createdAt DateTime @default(now())
}

enum AdminRole {
  OWNER
  STAFF
}

model Client {
  id            String   @id @default(cuid())
  businessName  String
  contactEmail  String   @unique
  passwordHash  String
  logoUrl       String?
  brandColors   Json?    // { primary, secondary, accent }
  toneKeywords  String[] // 品牌语气关键词
  status        ClientStatus @default(ACTIVE)
  creditLimit   Int?     // 运营方给这个客户设的月度出图上限(张),null = 不限
  createdAt     DateTime @default(now())

  channels      ConnectedChannel[]
  submissions   Submission[]
  auditLogs     AuditLog[]
}

enum ClientStatus {
  ACTIVE
  SUSPENDED
}

model ConnectedChannel {
  id          String   @id @default(cuid())
  clientId    String
  client      Client   @relation(fields: [clientId], references: [id])
  platform    Platform
  ayrshareProfileKey String   // 该客户对应的 Ayrshare Profile-Key(加密存储)
  ayrshareRefId      String   // Ayrshare 返回的 profile 标识
  connected   Boolean  @default(false)
  accountHandle String?
  connectedAt DateTime?
  needsReconnect Boolean @default(false)

  @@unique([clientId, platform])
}

enum Platform {
  INSTAGRAM
  FACEBOOK
  LINKEDIN
  TIKTOK
  YOUTUBE
  PINTEREST
  X
  GOOGLE_BUSINESS
  // 其余 Ayrshare 支持的平台按需追加
}

model Template {
  id                String   @id @default(cuid())
  orshotTemplateId  Int      // Orshot 官方模板库 ID,或自建模板 ID
  name              String
  category          String   // 行业标签:烘焙 / 美容 / 地产 / 健身...
  thumbnailUrl      String
  fieldSchema       Json     // [{ paramId: "title", label: "标题", type: "text", maxLength: 40 }, ...]
  isActive          Boolean  @default(true)
  createdAt         DateTime @default(now())

  submissions       Submission[]
}

model Submission {
  id            String   @id @default(cuid())
  clientId      String
  client        Client   @relation(fields: [clientId], references: [id])
  templateId    String
  template      Template @relation(fields: [templateId], references: [id])
  briefText     String   // 商家填的一段话简介(用于 AI 生成文案 + 部分字段)
  fieldValues   Json     // 商家针对模板字段填的具体值(如果走"逐字段填写"方案)
  uploadedPhotos String[] // 商家上传的照片 URL

  status        SubmissionStatus @default(DRAFT)
  generatedAssetUrl String?
  captionText   String?
  hashtags      String[]

  targetPlatforms Platform[]
  scheduledAt   DateTime?
  ayrsharePostId String?
  publishStatus  String?  // Ayrshare 回传的发布状态
  errorMessage   String?

  orshotCreditsUsed Int  @default(0)

  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
}

enum SubmissionStatus {
  DRAFT
  GENERATING_CAPTION
  GENERATING_ASSET
  PENDING_REVIEW
  SCHEDULED
  PUBLISHED
  FAILED
}

model AuditLog {
  id        String   @id @default(cuid())
  clientId  String?
  client    Client?  @relation(fields: [clientId], references: [id])
  actorType String   // "admin" | "client" | "system"
  actorId   String?
  action    String
  metadata  Json?
  createdAt DateTime @default(now())
}
```

**风险点(N+1 / 分页)**:M10 历史列表、M11 客户列表都可能随数据量增长,`Submission`/`Client` 列表查询必须自带分页(cursor-based),`ConnectedChannel` 按 clientId 批量预加载,不逐条查询 Ayrshare。

## 7. 风险点

1. **Ayrshare 计费按客户数阶梯递减,前期(<10 客户)单客户成本较高(~$30/客户)**,需要在商业模式里预先算好毛利,不能等客户量做大才发现前期亏本。
2. **Orshot Social Publishing 的客户自助连接机制未经证实**——本方案不使用 Orshot 发布功能,只用 Ayrshare,规避此风险,但如果未来想合并成一家,需要先跟 Orshot 官方确认。
3. **Ayrshare 从 2026-03-31 起 X(Twitter)发布需要客户自备 OAuth 1.0a Key**,意味着每个客户如果要发 X,需要额外指导他们去 X 开发者后台申请,不是纯免配置,产品文案里要提前说明。
4. **模板字段映射维护成本**:每新增一个 Orshot 模板给商家选,运营方都要手动去模板编辑器里核对参数名、录入 `fieldSchema`,这是持续性的人工运营工作,不是一次性开发工作,需要在 M4 后台做一个方便录入的界面,而不是让运营方直接改数据库。
5. **异步任务可靠性**:Orshot 渲染、Ayrshare 发布都可能失败/超时,`Submission` 状态机必须能安全重试(幂等),避免重复扣费/重复发布——两家 API 都支持 Idempotency-Key,设计阶段必须用上。
6. **多租户数据隔离**:每个 Client 的 Logo、Ayrshare Profile-Key 属于敏感数据,数据库层面要按 `clientId` 强制过滤,不能出现 A 商家看到 B 商家数据的越权漏洞——鉴权探针必须覆盖这一条。
7. **法务边界**:本项目商业模式建立在"Ayrshare/Orshot 条款允许 agency 用法"的调研结论上,调研基于 2026-09 时点的公开条款页面,条款可能变更,建议在正式签约付费套餐前,给对应厂商发一封邮件书面确认用法合规,留存回执作为后续依据。

## 8. 架构边界评估(大改专用)

- 这是全新项目,不存在"复用现有代码"的问题
- N+1 风险:见第 4 节 schema 说明
- 分页风险:客户列表、历史记录列表、任务监控列表三处必须分页,不允许一次性拉全表
- 架构边界:M6(文案)与 M7(出图)设计为可独立替换的两个服务适配层(`lib/providers/llm.ts`、`lib/providers/orshot.ts`、`lib/providers/ayrshare.ts`),任何一家上游服务被替换,只改适配层,不动业务逻辑层——这是应对"调研结论可能过时/厂商条款变化"的架构保险

## 9.1 M5 内容提交流程(2026-09-27 修订,纠正了第 9 节的原假设)

原假设(一段话 + AI 拆解填字段)已被用户明确纠正,原话见 `docs/20260927-social-agency-需求原话.md`"M5 内容提交流程澄清"一节。修订后的流程:

1. **选模板**:客户只能从运营方在 M4 筛选/上架的模板里选(`isActive=true`),看不到 Orshot 原始模板库,不看到 Orshot/Ayrshare 品牌——这是"白标"的核心。
2. **模板详情页 = 逐字段编辑 + 预览**:按 `Template.fieldSchema` 逐个字段填(不是写一段话),`type: 'image'` 字段默认带入 `client.logoUrl`(可换),`type: 'text'` 字段客户手填,`type: 'ai_generated'` 字段不在这里填,由 M6 事后生成。左侧/上方展示预览图,随填写更新。
3. **预览机制(技术选型,2026-09-27 确认)**:比较过三种做法——(a)自建表单 + 停顿/点按钮后调 Orshot 真实 `render` 出预览图,(b)同上但自动防抖刷新,(c)直接嵌入 Orshot 官方 Embed 设计器(`docs.orshot.com/orshot-embed`,真正逐字跟着变,但要 Orshot **Grow 档 $160/月起**才能去掉 Orshot 自己的品牌水印,免费/Launch 档看不到"去品牌"选项)。**MVP 阶段选 (b):自建表单 + 防抖(停顿约 1.5-2 秒)调真实 Orshot render 刷新预览**,免费额度(每月 100 credit,不用信用卡)就够演示和早期验证用,预览用的就是最终会用的同一条 `renderTemplate` 调用,不会出现"预览和实际发布效果对不上"的问题。Embed 方案作为未来可选升级路径保留,不影响现在的架构——两条路线都走 `lib/providers/orshot.ts` 这一层,以后要换成 Embed 只需替换模板详情页这一个组件。
4. **确认使用**:客户点"确定使用该模板"后触发 M6(AI 文案生成社交平台配文,不是生成图片内容)+ M7(用客户刚填的字段值,再走一次真实渲染出正式成品图),而不是"一段话讲给 AI 听,AI 猜着填"。
5. **账号绑定与发布**沿用已完成的 M3(T6)+ 待做的 M9;定时发布见 M9/M12。
