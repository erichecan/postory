# 验收标准与测试用例

对应 DEV-PLAN.md 附录 A。分两栏,格式沿用全局 CLAUDE.md 的验收原则:技术验收(A 类,运营方自证)与定性验收(B 类,需要用户/商家肉眼确认)分开;状态只有三种——**符合 / 待你确认 / 没做到(附原因）**。

## 一、场景化验收标准(A 类,技术自证)

| 场景 | 来源 | 验收标准 | 验证方式 |
|---|---|---|---|
| 未连接社交账号的平台不能被选为发布目标 | [我推断的] M5 设计 | 前端提交表单里未连接的平台勾选框禁用;后端 `createSubmission` 对非法平台返回 400 | 单元测试 + E2E |
| 商家 A 无法看到商家 B 的任何数据 | [我推断的] 多租户隔离要求 | 所有 Client 侧查询强制带 `clientId` 过滤;跨租户访问返回 403/404 | 鉴权探针 + 单元测试 |
| Orshot 渲染失败不会导致重复扣费 | [我推断的] Idempotency 设计 | 同一 `submissionId` 重复触发渲染,Orshot 侧用同一个 Idempotency-Key,不产生二次计费 | 集成测试(mock Orshot 返回同一 key 的重放响应) |
| Ayrshare 发布失败会给出可理解的错误提示,而不是原始错误码 | [我推断的] M9 异常处理设计 | `CHANNEL_NOT_CONNECTED`等错误码被映射成中文提示文案 | 单元测试(mock 各错误码) |
| 客户额度用尽后新提交被拒绝,而不是生成失败才发现 | [我推断的] M11 设计 | `createSubmission` 前置校验 `checkCreditLimit`,超额直接 400,不进入生成流水线 | 单元测试 |
| 定时任务批次里单条失败不影响其他记录处理 | [我推断的] M12 设计 | Cron 处理器逐条 try/catch,一条抛异常不中断循环 | 单元测试(mock 3 条记录,中间 1 条抛错,断言另外 2 条仍被处理) |
| 历史记录/客户列表在数据量大时不全表扫描 | [我推断的] 性能要求 | 列表查询使用 cursor 分页 + 索引;`EXPLAIN` 确认走索引 | 查询探针(Prisma query log 断言查询数不随数据量线性增长) |
| 鉴权:写操作(发布/连接渠道)在无 token / 错 token / 低权限三种情况下分别返回 401/401/403 | [我推断的] 全局 CLAUDE.md 铁律 | 见下方 verify.sh 鉴权探针 | 自动化脚本 |

| 用例编号 | 模块 | 前置条件 | 步骤 | 预期结果 |

| TC-02 | M5 | 商家已连接至少 1 个渠道 | 1. 选模板 2. 填简介 3. 选目标平台(含未连接的平台) | 未连接平台的勾选框不可点击 |
| TC-03 | M6+M7 | 商家提交了合法内容 | 1. 提交后等待 | 状态依次变化 DRAFT → GENERATING_CAPTION → GENERATING_ASSET → PENDING_REVIEW;最终有 captionText 和 generatedAssetUrl |
| TC-04 | M8 | Submission 处于 PENDING_REVIEW | 1. 点击"确认发布"并选择"立即发布" | 状态变为 PUBLISHED,Ayrshare 返回的 ayrsharePostId 有值 |
| TC-05 | M8 | Submission 处于 PENDING_REVIEW | 1. 选择"定时发布",选一个未来时间 | 状态变为 SCHEDULED;到点后 Cron 任务把状态同步为 PUBLISHED |
| TC-06 | M9 异常 | 商家选的平台连接已过期(needsReconnect=true) | 1. 尝试发布 | 返回清晰提示"请先重新连接该平台",不是原始错误码 |
| TC-07 | M11 | 运营方给某客户设 creditLimit=5,该客户本月已用 5 | 1. 商家尝试新建 Submission | 提交被拒绝,提示"本月额度已用完,请联系客服" |
| TC-08 | 多租户 | 两个不同商家账号 A、B | 1. 用 A 的会话尝试访问 B 的 submissionId 详情页 | 返回 403 或 404,不能看到 B 的数据 |
| TC-09 | 鉴权 | 未登录 | 1. 直接访问 `/dashboard` | 跳转登录页,不能看到任何数据 |
| TC-10 | 鉴权 | 商家账号 | 1. 尝试访问 `/admin` 任意页面 | 返回 403 |

## 四、自动化测试用例设计

分两层:**单元测试**(Vitest/Jest,针对 `services/*.ts` 业务逻辑,mock 掉三个 Provider 适配层)与**端到端测试**(Playwright,跑真实页面交互,Provider 层用测试环境的 sandbox key 或 mock server)。

### 4.1 单元测试清单

| 测试文件 | 覆盖点 |
|---|---|
| `services/__tests__/submission.test.ts` | createSubmission 的平台校验、额度校验 |
| `services/__tests__/generateContent.test.ts` | M6+M7 流水线的状态流转、失败降级(LLM 失败时的保底文案)、Idempotency-Key 是否正确传递 |
| `services/__tests__/publish.test.ts` | M9 的错误码映射、schedule vs publish 分支 |
| `services/__tests__/cronProcessor.test.ts` | M12 单条失败不影响其他记录 |
| `middleware/__tests__/auth.test.ts` | 三套角色的路由访问控制 |

### 4.2 单元测试示例代码(骨架,供实现阶段直接扩展)

```typescript
// services/__tests__/generateContent.test.ts
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { generateContent } from '../generateContent'
import * as orshot from '../../lib/providers/orshot'
import * as llm from '../../lib/providers/llm'

describe('generateContent', () => {
  beforeEach(() => {
    vi.restoreAllMocks()
  })

  it('LLM 失败时使用保底文案,流程继续而不是整体失败', async () => {
    vi.spyOn(llm, 'generateCaption').mockRejectedValue(new Error('LLM timeout'))
    const renderSpy = vi.spyOn(orshot, 'render').mockResolvedValue({
      assetUrl: 'https://example.com/a.png',
      creditsUsed: 1,
    })

    const result = await generateContent({
      submissionId: 'sub_1',
      briefText: '本周新品上市',
      toneKeywords: ['活泼'],
    })

    expect(result.captionText).toContain('有新动态')
    expect(renderSpy).toHaveBeenCalledOnce()
    expect(result.status).toBe('PENDING_REVIEW')
  })

  it('Orshot 渲染失败时状态变为 FAILED,并记录 errorMessage', async () => {
    vi.spyOn(llm, 'generateCaption').mockResolvedValue({
      captionText: '测试文案',
      hashtags: ['#测试'],
    })
    vi.spyOn(orshot, 'render').mockRejectedValue(new Error('INSUFFICIENT_CREDITS'))

    const result = await generateContent({ submissionId: 'sub_2', briefText: 'x', toneKeywords: [] })

    expect(result.status).toBe('FAILED')
    expect(result.errorMessage).toMatch(/INSUFFICIENT_CREDITS/)
  })

  it('对同一 submissionId 重复调用,Orshot 请求携带相同 Idempotency-Key', async () => {
    const renderSpy = vi.spyOn(orshot, 'render').mockResolvedValue({
      assetUrl: 'https://example.com/a.png',
      creditsUsed: 1,
    })

    await generateContent({ submissionId: 'sub_3', briefText: 'x', toneKeywords: [] })
    await generateContent({ submissionId: 'sub_3', briefText: 'x', toneKeywords: [] })

    const keys = renderSpy.mock.calls.map((c) => c[0].idempotencyKey)
    expect(keys[0]).toBe(keys[1])
  })
})
```

```typescript
// services/__tests__/publish.test.ts
import { describe, it, expect, vi } from 'vitest'
import { schedulePublish } from '../publish'
import * as ayrshare from '../../lib/providers/ayrshare'

describe('schedulePublish', () => {
  it('渠道未连接时返回中文友好提示,不暴露原始错误码', async () => {
    vi.spyOn(ayrshare, 'post').mockRejectedValue({
      code: 'CHANNEL_NOT_CONNECTED',
      message: 'instagram is not connected',
    })

    const result = await schedulePublish({ submissionId: 'sub_1', platforms: ['instagram'] })

    expect(result.status).toBe('FAILED')
    expect(result.userMessage).toBe('请先重新连接该平台后再发布')
  })

  it('scheduledAt 为空时调用 publish 而非 schedule', async () => {
    const postSpy = vi.spyOn(ayrshare, 'post').mockResolvedValue({ postId: 'p1' })
    await schedulePublish({ submissionId: 'sub_2', platforms: ['instagram'] })
    expect(postSpy).toHaveBeenCalledWith(expect.objectContaining({ scheduleDate: undefined }))
  })
})
```

### 4.3 端到端测试示例(Playwright,骨架)

```typescript
// e2e/submit-flow.spec.ts
import { test, expect } from '@playwright/test'

test('商家完整提交-审核-发布流程', async ({ page }) => {
  await page.goto('/login')
  await page.fill('#email', 'test-client@example.com')
  await page.fill('#password', 'test-password')
  await page.click('button[type=submit]')

  await page.goto('/dashboard/templates')
  await page.click('[data-testid=template-card]:first-child')

  await page.fill('#briefText', '本周新品上市,欢迎试吃')
  await page.check('[data-testid=platform-instagram]')
  await page.click('button:has-text("提交")')

  await expect(page.locator('[data-testid=submission-status]')).toHaveText(/生成中/, {
    timeout: 5000,
  })

  // 轮询等待生成完成(测试环境用 mock server 加速,不真实等待 Orshot)
  await expect(page.locator('[data-testid=submission-status]')).toHaveText('待审核', {
    timeout: 30000,
  })

  await page.click('button:has-text("确认发布")')
  await page.click('button:has-text("立即发布")')

  await expect(page.locator('[data-testid=submission-status]')).toHaveText('已发布', {
    timeout: 30000,
  })
})

test('未连接的平台不能被选中', async ({ page }) => {
  // ...登录省略
  await page.goto('/dashboard/submit/template_1')
  const tiktokCheckbox = page.locator('[data-testid=platform-tiktok]')
  await expect(tiktokCheckbox).toBeDisabled()
})
```
