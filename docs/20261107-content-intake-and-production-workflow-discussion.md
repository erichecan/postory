# PoStory 客户接入与内容生产流程（讨论稿）

- **状态：**持续讨论中；不是开发规格或已实现承诺
- **版本：**v3.3
- **更新日期：**2026-11-08
- **用途：**记录从创建客户专属链接，到资料收集、审核、客户建档、商品识别、素材评估、营销日历和图片生成成本的已讨论规则。后续讨论继续追加在本文档，并更新状态与版本。

## 一、目标与已知边界

PoStory 暂不向客户或代理商开放系统账号。客户通过专属链接提交资料和查看进度；代理商可把链接转发给客户，但不登录后台管理客户。客户通过资料审核后建立的是**后台客户档案**，不代表给客户创建登录账号。

本稿已覆盖从客户接入、素材池、视频识别、目标选择、营销日历、内容生成/审核，到社媒授权、自动排期、失败处理和管理员复盘的讨论流程，并在第十四节定义阶段验收标准。该流程仍未完成开发规格或端到端实测；20 条内容的目标模板与分配、个性化整月排程、视频重剪，以及多项指标的实际可用性仍待验证。

## 二、已确认的流程规则

### 2.1 专属链接由谁创建

- 由 PoStory 管理员在内部后台创建专属链接。
- 创建时选择链接归属：PoStory，或某个代理商。
- 选择页面展示品牌：PoStory Logo，或对应代理商 Logo。
- 链接归属不会因代理商转发而改变。
- 客户和代理商目前都不登录后台。
- 链接创建入口建议为内部后台的“客户接入 → 创建专属链接”。

专属链接能说明这次提交来自哪条链接，但本身不能证明实际填写者就是客户本人。系统可识别异常信号并上报，不能单靠链接断定身份。

### 2.2 客户资料可先提交，制作前必须完成付款条件

- 客户可未付款先填写资料、接受自动完整性检查、处理异常并建立客户档案。
- **任何制作工作开始前，必须已付款，或由后台登记线下结算。**
- 制作包括商品图片/视频画面 AI 识别，以及后续商品整理与优化、内容策划、图片生成等会消耗模型或制作资源的步骤。
- 未付款且未登记线下结算的项目停在“待付款”，不启动制作。

### 2.3 异常审核闸门

- 资料不全：系统自动列出缺项，通知客户通过原链接补充。
- 疑似冒用链接、客户归属不符、品牌/联系人信息冲突、资料彼此矛盾：暂停自动流程并通知管理员。
- 管理员审核通过后才建立正式客户档案并进入后续准备；需要客户解释时先要求补充；不通过时由管理员决定拒绝或继续核实。
- 完整且无异常的资料可由系统自动通过并建立正式客户档案。

### 2.4 首版上传数量与大小上限（建议默认值）

为了让客户能一次提交常用素材，同时控制上传失败、识别等待和存储压力，首版按以下上限设计：

| 素材 | 单个限制 | 每个客户项目限制 | 上传页提示 |
|---|---:|---:|---|
| 图片 | 每张不超过 20 MB | 最多 30 张，合计不超过 300 MB | JPG、PNG、HEIC；超限时提示压缩或换图 |
| 视频 | 每段不超过 180 秒、250 MB | 最多 5 段，视频合计不超过 1 GB | MP4、MOV；超时或超大时提示剪短/压缩 |
| 全部素材 | — | 图片和视频合计不超过 1.3 GB | 上传前显示已用数量和剩余空间 |

视频长度定为 **最多 3 分钟一段、最多 5 段**；允许分多段上传，系统逐段识别并合并重复商品候选。达到上限后，客户可删除或替换文件；需要更多素材时由管理员评估后扩容。单文件大小上限与总量上限同时生效。上传页逐项显示进度、失败原因和重试入口。上述是首版产品默认值，先作为讨论基准；后续可根据实测上传成功率、识别等待和存储费用调整。

## 三、客户资料表单：连续引导、尽量点选

表单采用一条连续流程，不把客户分成两次提交。自动保存；客户可一次填完，也可用同一链接稍后继续。问题用日常说法，选择题优先；只有店名、地址、电话、网站、准确的商品名称等必须精确的信息才输入。能从链接预填的代理商、Logo、已知品牌名等由客户确认，不重复录入。

### 3.1 店铺和经营内容

| 引导问题 | 输入方式 | 用途 |
|---|---|---|
| “你的店希望大家叫什么？” | 预填确认；必要时改店名 | 确认品牌名称 |
| “选一个最接近的就好。你主要做哪一类生意？” | 餐厅、美容/美甲、零售、家居/维修、健康/健身、其他服务、其他 | 选择行业内容规则 |
| “最近最希望我们先介绍什么？” | 招牌商品、新品、热门服务、季节商品、店铺环境、团队/制作过程、近期活动、还没想好；可多选 | 确定内容重点 |
| “你希望这些内容帮你做什么？” | 让更多人认识我的店、吸引客户到店、增加预约、介绍新品/服务、提醒近期活动、保持账号活跃、还不确定 | 了解客户目标，不要求填写营销术语 |
| “近期有没有想安排的活动或重要日期？” | 选择节日/日期；活动价格和规则需填写或上传确认材料 | 避免编造优惠或时间 |

### 3.2 地址、联系和服务方式

| 引导问题 | 输入方式 | 用途 |
|---|---|---|
| “客户要来店里，应该导航到哪里？” | 地址联想；也可选上门服务或只在线经营 | 地址或服务区域 |
| “客户想打电话预约时，应该拨哪个号码？” | 电话输入；也可选只接受线上预约/暂不公开电话 | 后续内容不误导联系方式 |
| “客户问今天几点营业，我们应该怎么回答？” | 按星期点选时间；也可选预约制、时间不固定、暂时不知道 | 避免错误营业信息 |
| “客户想预约或购买时，通常怎么做？” | 电话、到店、社交平台私信、预约网站、网店；选网站后再填链接 | 确认行动入口 |
| “客户可以先去哪里看看你的店？” | 可贴官网或社交账号链接 | 供品牌资料参考 |

### 3.3 品牌感觉和说话方式

| 引导问题 | 点选选项 | 用途 |
|---|---|---|
| “你希望客户觉得你的店是什么样的？” | 亲切好相处、专业靠谱、温暖舒服、活泼有趣、简洁清爽、精致讲究、自然朴实、热闹有活力；可多选 | 设定大致品牌感觉 |
| “有没有哪种感觉不适合你的店？” | 从同一组词卡点选排除；可选不确定 | 避免不合适风格 |
| “你喜欢哪种图片感觉？” | 明亮自然、温暖柔和、干净简洁、色彩鲜艳、精致高级、真实生活感；可选按商品和店面建议 | 用图片示例代替设计术语 |
| “你已有 Logo 或固定颜色吗？” | 上传 Logo、有固定颜色（点选色卡）、都没有、不确定 | 有则保留，无则系统建议 |
| “内容说话更像哪一种？” | 热情店主、耐心专业人员、轻松朋友、简单直接、按现有页面风格 | 设定文案语气 |

### 3.4 图片、视频和其他资料

先让客户点选素材种类，再批量上传：商品照片、店面照片、服务/制作过程、团队照片、Logo、菜单/价目表/商品说明、暂时没有照片。

- 商品照片提示：“尽量拍清楚商品本身。正面、细节和不同颜色都可以上传。”
- 店面照片提示：“上传店门、店内或工作区域，帮助我们了解真实环境。”
- 服务/制作过程提示：“上传你希望客户看到的工作过程。”
- 资料上传后由系统按种类识别并请客户确认；不要求客户逐张写描述。
- 每个文件旁边都显示素材类型标签，客户可点选或修改：商品照片、店面/环境照片、使用场景、制作/服务过程、团队、Logo/包装/价目资料、其他。视频另有用途标签：商品展示、商品使用、店铺介绍、制作过程、顾客体验、其他。系统先自动建议标签，客户不必逐个打字；标签不确定时标为“待确认”。
- 上传时不强迫客户逐文件填写说明；可选填“这组素材最想展示什么”，并提供“商品本身 / 店铺环境 / 使用过程 / 暂时不确定”等点选项。客户后来在确认页选择本次制作范围；不展示文件来源图片或视频时间点。
- 询问“哪些内容需要保留或忽略？”时提供点选：保留品牌标志、保留包装文字、忽略杂乱背景、忽略货架/摆设、没有特别要求。
- 若图片中有可辨认的人，询问是否允许用于宣传；不确定时不使用可辨认人像。
- 商品识别前后都不得仅凭图片猜写价格、成分、功效、规格等事实。

### 3.5 喜欢的参考内容

此项**选填**，不要求客户判断谁是竞品或分析商业模式。

引导语：“有没有哪家店的图片或帖子，你觉得看起来不错？”客户可上传截图、贴链接或选“暂时没有”。如果提供参考，再点选喜欢的部分：颜色、照片感觉、文字、店铺氛围、活动想法、整体喜欢但说不上来。

页面说明：“参考内容只帮助我们了解你喜欢什么感觉，不会照搬别人的图片或文字。”没有参考时根据客户自己的资料和已维护的行业规则提出原创方向，不自动搜索同行。

### 3.6 平台、语言与提交确认

- “你希望我们准备哪些平台的内容？”点选 FB、Instagram、TikTok 等，可多选或选择“帮我建议”。
- “客户希望看到什么语言？”点选语言，可多选或选择“跟现有页面相同”。
- 提交前展示系统整理的简短摘要，客户点选确认或返回修改，不让客户重新抄写一遍。
- 提交后告知：“资料已收到。我们会先检查是否完整。你可以关闭页面，稍后用原链接回来查看；如果需要补充，我们会告诉你该补哪一项。”

## 四、提交、检查和建立客户档案

建议的状态顺序：

```text
待客户提交 → 待系统检查
                  ├─ 缺资料 → 待客户补充 → 待系统检查
                  ├─ 有异常 → 待管理员审核 → 通过 / 补充核实 / 拒绝
                  └─ 完整且无异常 → 自动通过
                                  ↓
                          建立正式客户档案
                                  ↓
                      待付款或待线下结算登记
                                  ↓
                     付款条件满足后进入制作
```

系统检查内容可包括必填项、字段格式、提交重复、链接预设归属是否冲突、资料前后是否矛盾、文件是否成功上传/可读取。访问频率或提交环境的变化可作为风险信号，不应单独作为欺诈结论。

## 五、商品清单识别与确认

### 5.1 客户确认节点与页面

客户确认发生在素材识别后、营销策划前，放在专属链接中的独立确认页面。付款条件满足后系统开始识别；识别完成后通知客户回来继续，不要求守候。客户确认的是本次制作范围和重点，不负责逐帧校对 AI。

客户页面不展示来源图片、视频时间点、AI 建议名称或可见特征。页面用简短选项确认“这次要做什么”：店铺介绍、促销活动、重点商品、商品组合；客户可补充或点选重点商品，也可指出遗漏。识别结果和素材是否足以制作要用简单状态说明，例如“素材够用”“素材有限，部分内容需用示意图”“建议补拍”。素材不足时给出补拍或接受示意图的选择；其他素材足够的内容可以继续。

宣传范围的确认要求按内容类型区分：**活动介绍、店铺介绍只需客户确认宣传范围；具体单品宣传必须有客户确认的菜单、价目表或商品名单。**单品资料未提供或无法对应时，系统不能从视频画面自行定名、补价格或规格；应提示客户补交/确认资料，并暂缓该单品内容。已具备资料的活动/店铺内容及其他单品可以继续，不因一项资料缺失卡住整个项目。

### 5.2 付款后才开始识别

商品照片 AI 识别属于制作。只有确认付款或登记线下结算后才启动。付款前可检查文件是否成功上传、资料是否完整，但不启动商品图片/视频的 AI 内容识别。

### 5.3 图片识别

图片素材按商品、店面环境、服务/团队等类别识别。系统内部提取候选商品、不同角度/颜色/款式关系和画面质量；货架、杂物和背景物默认不作为制作重点。客户界面不显示系统推测的商品名称或可见特征；若需要准确商品名称、价格、成分、功效或规格，使用客户确认的商品资料。

同一商品的不同角度、颜色或款式先归组成候选商品组。不同颜色可以先作为同一商品的变体；不确定是否同款时标出并让客户确认。AI 不可见的信息只能标为未知或候选，不能作为商品事实。

### 5.4 视频识别：主题、商品候选与活动关系

多商品视频不能只做“抽帧 → 识别商品 → 裁商品图”。工作台应同时理解整段视频的营销主题、其中值得关注的商品候选，以及它们之间的活动或组合关系。预算挑战、店铺介绍、促销巡店等视频可能既有整段内容价值，也有单品内容价值；不强制把每段视频拆成单品广告，也不把镜头中所有商品都当作制作清单。

建议的视频处理顺序：

1. **逐段检查输入：**核对视频可否解码、画面/声音是否存在、时长和画面规格；客户填写的描述只作线索，不能直接视为事实。
2. **全片初筛抽帧：**每段视频先取最多 12 帧，覆盖开头、中段和结尾。均匀取样作为全片扫描的基线，不称为“关键帧”，也不保证拍到每件商品。
3. **按需补抽：**若初筛发现商品/主题出现密集、画面切换快或内容覆盖不足，可因新场景、候选商品变化或主题线索再补最多 6 帧；每段视频总计最多 18 帧。补抽仍不足以判断时标为待核实，不继续无限加帧。这是首版测试上限，尚未由代表性素材验证。
4. **理解画面和声音：**读取画面中的场景、商品候选、字幕/价签等文字；有可识别口播时可转写以辅助理解视频主题。画面文字和口播都只是线索，不能单独证明价格、型号、库存或优惠。
5. **识别整段主题并整理候选：**判断是预算挑战、店铺介绍、促销活动、商品使用/展示等；保守合并重复商品，区分不同商品或款式。画面清楚、重复出现、停留较久或被口播/字幕强调的内容优先作为候选；一闪而过或无法辨认的货品不自动列为重点。
6. **关联活动与商品：**整理哪些候选属于同一促销、预算主题、套装或组合。客户提供的菜单、价目表或商品名单用于核对单品；客户描述、OCR 文字和口播不能替代客户确认的商品事实。
7. **输出制作范围建议和缺口：**区分可做的店铺/活动内容、可对应客户资料的单品内容、素材有限的内容及待核实项。具体单品资料缺失时只暂缓对应单品，不阻挡已有依据的店铺/活动内容。
8. **客户确认制作范围：**客户通过简短选项确认本次做店铺介绍、促销活动、重点商品或商品组合，并可补充遗漏。客户无需逐帧校对，也不需要逐条纠正 AI 猜测。

内部识别结果至少包含：主题类别及简述、内容/商品候选及其关系、候选置信程度、可用性状态、待核实事实，以及供后台质检的来源依据。客户界面不展示来源图片、视频时间点、系统建议名称或可见特征；有客户提供的商品名单时，只使用客户提供的名称供其选择范围。没有名单时，客户可确认店铺或活动范围；若要做具体单品内容，先补充或确认菜单、价目表或商品名单。商品名称、价格、型号、库存和优惠等事实以客户确认资料为准。

**现状提醒：**12 帧初筛、最多 6 帧自适应补抽（总上限 18 帧）是已同意的首版测试规则，不代表已经实现或证明足够。产品不承诺“关键帧识别”；要根据代表性多商品素材检查漏项，再调整上限和补抽条件。

### 5.5 上传文件标注和视频额度

- 上传入口采用“先选素材种类，再批量上传”；上传后每个文件旁显示自动建议的种类标签，客户可快速确认/更改，不要求逐个写描述。
- 视频标签至少包括商品展示、商品使用、店铺介绍、制作/服务过程、顾客体验、其他；无法判断时显示“待确认”。
- 首版建议额度：**最多 5 段视频，每段最长 180 秒、每段不超过 250 MB；最多 30 张图片，每张不超过 20 MB；单项目全部素材合计不超过 1.3 GB。**超限时先让客户替换/删减；额外额度由管理员处理。
- 这是产品首版的明确建议值，尚未经过真实客户上传和成本数据验证；实施时应保留管理员调高项目额度的能力。

### 5.6 识别等待与客户确认界面（讨论方案）

- 识别异步运行，客户不需要停留在上传页。上传后立即显示“已收到，正在整理”，完成后通过原专属链接的页面状态告知可继续确认；若有通知渠道，再发提醒。
- 目前没有 PoStory 生产环境基准，不能承诺精确完成时间。首版体验目标建议：常见小批量（约 10 张图片或 1 段 1–3 分钟视频）多数在 **1–3 分钟**内完成；达到 30 张图片和 5 段视频上限时，目标 **不超过 10 分钟**。这是产品体验目标，不是已测性能承诺；超时应显示仍在处理中和预计更新状态，不得让客户误以为卡死。
- 试运行需记录上传结束、开始识别、完成识别的时间，按真实文件数量、视频时长和排队情况测出 P50/P95，再调整对客户显示的时间承诺。长视频不是“模型一次读完整个视频”：先在服务器抽取/去重候选画面，再分批识别。
- 客户界面按本轮要求保持简洁：**不展示来源图片、不展示视频时间点、不展示系统建议名称或可见特征**。避免客户面对一堆 AI 猜测逐条纠错。
- 对“店铺介绍、促销巡店”这类多商品视频，遵循 5.4 的视频主题、商品候选、活动关系整理方式；不把所有入镜商品自动当作制作重点。
- 客户确认页给出简短范围选项，例如“店铺介绍 / 促销活动 / 重点商品 / 商品组合”，以及“都包括了，继续 / 需要补充或更正”。客户不必逐帧验货；若要发布准确单品信息，必须有客户确认的商品资料。

### 5.7 视频识别用量与费用估算

按首版抽帧规则估算：每段视频最多 180 秒，先抽 12 帧，必要时补抽最多 6 帧（总上限 18 帧）；一个项目最多 5 段视频。代表帧假设为 576 × 1024，并按视觉模型 GPT-6 Luna 的图像输入计费规则估算，每帧约 692 个图像输入 token。下表先按 12 帧初筛计算；若全部视频都补满 18 帧，5 段视觉输入上限约 62,300 token，实际费用随模型和图像细节变化。

| 处理范围 | 估算用量 | 估算 API 费用 |
|---|---:|---:|
| 1 段视频，最多 12 帧 | 约 8,300 个图像输入 token | 约 $0.0008，未计文字输出 |
| 5 段视频，最多 60 帧 | 约 41,500 个图像输入 token | 约 $0.0042，未计文字输出 |
| 5 段视频口播转写，合计最多 15 分钟 | 按音频时长计费，不按 token | 约 $0.0675 |
| 5 段视频，画面识别并含口播转写 | 约 41,500 个图像输入 token，另有转写 | 约 $0.072，另加少量文字指令/结果整理用量 |

口播转写为可选辅助：它可帮助理解活动主题和口播中提及的商品，但不能单独证明商品型号、价格或优惠事实。若关闭转写，只处理画面，5 段视频的视觉输入费用约半美分；加入转写后合计估算约 7–8 美分。以两段示例视频（约 79 秒和 43 秒）为例，若各最多取 12 帧，视觉输入约 16,600 token；两段口播转写约 2 分钟，约 $0.009。

以上为基于当前官方标准费率的预算估算，不是 PoStory 实测账单。实际费用会随所选模型、画面大小、抽帧数、OCR/补抽、输出长度、重试而变化；实现时必须记录 API 返回的实际用量，并用真实的多商品促销视频验证 12 帧初筛加按需补抽的覆盖效果。图像规则参考 [OpenAI 图像输入计费说明](https://developers.openai.com/api/docs/guides/images-vision)，模型费率参考 [OpenAI API 价格表](https://developers.openai.com/api/docs/pricing)，口播转写参考 [GPT Transcribe 价格](https://developers.openai.com/api/docs/models/gpt-transcribe)。

### 5.8 客户确认并锁定制作范围

- 客户必须确认本次制作范围和重点商品/活动，包括系统认为把握较高的内容；确认的是客户想宣传什么，不是 AI 的猜测是否正确。
- 客户可补充重点商品或从已提交的价目表/商品资料中点选；系统内部可以保留识别候选和来源证据供质量检查，但客户界面按 5.6 的约定不展示来源图片/时间点或 AI 建议名称/特征。
- 活动/店铺介绍只需客户确认宣传范围；具体单品宣传必须上传或确认菜单、价目表或商品名单，并能把内容对应到资料。缺少单品资料只暂停对应单品，不影响其他有依据的内容继续。
- 全部完成后点“确认制作范围并继续”。未确认范围，后续商品资料整理、策划和出图不启动。
- 确认后锁定该版制作范围，客户不能自行修改，避免后续成品依据被悄然改变。
- 若之后发现错误，需要管理员处理；事后更正对生产、费用和成品的影响尚未定。

### 5.9 客户素材池：按客户隔离、按制作周期整理

素材池是**同一客户在一个制作周期内**共用的已上传素材和已确认信息，不是跨客户共享的文件夹，也不是把所有历史促销混为一谈。不同客户的素材池必须完全隔离；同一客户新周期可引用其稳定品牌和商品资料，但不能默认沿用过期促销信息。

素材池分为四层：

1. **客户长期资料：**相对稳定的店铺地址、Logo、品牌风格、长期营业时间和常规服务。更新后保留版本，避免旧信息被后续内容继续使用。
2. **本期原始素材：**本次上传的图片、视频、商品资料、价目表和促销信息。保留原文件、上传时间、客户标注和使用限制。客户填写的描述只是线索，不自动成为事实。
3. **内部整理结果：**店铺/环境/服务素材、商品候选及重复来源、促销/预算/组合主题、素材质量和待核实的价格/型号/优惠期限。识别证据供后台检查；客户界面不展示来源图片/时间点或 AI 建议名称/外观特征。
4. **可制作的内容机会：**基于本期素材整理出活动整体、预算/组合、重点商品、店铺/服务介绍等候选方向，同时列明事实和素材缺口。候选机会不等于承诺的成品数量；不足以可靠制作的内容不能为了凑数硬做。

素材整理应保守合并：只有证据足以判定为同一商品时才跨文件归并；同品类但型号不确定时先分开或待核实。长期销售商品可在新周期引用已确认资料，但价格、库存、促销和季节活动必须有有效期，过期后不得直接进入新内容。

建议周期流程：客户上传本期素材 → 系统整理本期素材池 → 客户确认本期制作范围 → 系统排营销日历 → 客户确认日历 → 逐条制作 → 周期结束时保留长期资料、标记促销过期并按保留规则处理原始文件。周期长度和原始文件保留期限仍待确定。

## 六、素材质量不足时的规则

系统自动检查清晰度、亮度、主体大小、遮挡、抖动/拖影等，不要求人工逐张审核。建议结果分为：

- **可用：**商品清楚，适合真实商品展示。
- **有限可用：**能辨认商品但细节有限，限制使用方式。
- **需要补充：**商品无法可靠辨认，给客户明确的补拍提示或其他制作选项。

可以自动做裁切、亮度和背景整理，但不能把看不清的商品文字、颜色、形状或细节当成真实修复。客户可选真实商品展示，或接受概念示意图。若图片质量有限但客户同意示意图，可继续制作；不再因素材少就默认停下。

任何不能保证真实还原商品外观的 AI 成品，都要在图片角落清楚标注：

> **AI 生成示意图｜商品外观以实物为准**

如平台裁切后看不清，配文也需保留说明。免责声明不能替代事实核对：价格、功效、成分、规格等仍只能使用客户确认的资料。客户确认过的商品清单保持锁定，客户可以为已确认商品补交更清楚的素材，但不因此增删商品。

对 20 条内容，生成前应先说明可用实拍素材能支持的内容，以及哪些会是示意图；不能把同一张低质量商品图反复包装成 20 张看似不同的实物宣传图。

## 七、参考内容与原创策划

- **不在默认流程中自动搜索或分析同行的 FB/IG 页面。**公开内容并不总能稳定读取，难以保证达到预期；因此不把这一步作为客户生产的前置环节，也不为此单独引入网页搜索 API 或费用。
- 客户仍可自愿提供喜欢的品牌、帖子、截图或链接，帮助表达偏好的颜色、图片感觉、文字语气或活动方向。链接不可访问时，可让客户上传截图或跳过。
- 没有客户提供的参考时，系统依据客户确认的商品、品牌感觉、经营目标和已维护的行业规则，直接提出原创内容方向；不虚构市场调研结论或同行数据。
- 参考内容只用于理解客户偏好，不照搬对方图片、文案、Logo 或独特设计。

## 八、商品确认后的营销策划与日历

本期素材池整理、制作范围确认、素材可用性说明完成后，客户先选择**本月主要目标**，再生成营销日历；不由系统替客户猜本月最想达成什么。客户从下列目标中选一个主要目标，也可以再选一个次要目标；如不确定，可选择让系统按现有资料建议。该选择题覆盖首版常见需求，已在本轮讨论确认：

- **让更多本地顾客认识这家店**；
- **吸引顾客到店**；
- **增加电话或预约**；
- **介绍新品或重点服务**；
- **宣传本月促销/活动**；
- **让社交账号持续有内容**；
- **暂时不确定，请系统按现有资料建议**。

系统再依据主要目标、可选次要目标、行业模板、本期已确认的商品/活动范围、客户资料和素材质量挑选主题并安排日历。若选择促销，但没有确认活动时间、价格或规则，系统不编造促销内容；可以请求补充，或把日历调整为已有资料支持的店铺/商品介绍。若选择预约或到店目标，相关电话、地址、预约方式必须来自客户确认资料。

营销日历向客户展示日期/周次、主题、希望顾客采取的行动、对应商品或活动、内容形式和所需素材。**默认让客户一次查看并确认整份日历，不要求逐条点选确认；逐条检查只作为客户主动选择的细看选项。**日历按目标安排内容比例，不为了填满数量强行加入不相关主题。

客户可直接整体确认，或提交一份集中修改意见。系统根据这份意见统一调整一轮，再请客户整体确认并锁定日历；锁定后开始逐条制作。此规则旨在让客户表达必要意见，同时避免无限往返。客户锁定日历后再提出主题或范围变化时，如何处理对进度和费用的影响，仍待确定。

### 8.1 从日历到制作单和图片提示词

制作单由工作台自动生成，不要求客户或管理员逐条撰写。工作台从已确认的日历、本期素材池、客户品牌设置和已核实事实中填入固定字段：主题与目标、对应商品/活动、可用素材、允许使用的事实、构图与平台画幅、品牌风格、禁用内容、是否为示意图及免责声明。信息不足或互相矛盾的条目进入待补资料状态，不得让提示词模型自行补成“事实”。

已确认的真实商品制作原则：**优先保留客户确认过的商品原图，由 AI 生成/调整背景、场景和构图，不让模型自由重画商品本身。**准确的商品名称、价格、促销文字、Logo 和免责声明在图像生成后用排版层叠加，避免模型拼错或改动关键文字。若原图无法可靠保留商品外观，则转为明确标注的 AI 示意图，不把它当作真实商品照。

图片提示词优先由行业模板和规则编译器生成；需要把结构化制作单转换成自然语言时，可让低成本文本模型一次批量整理一组制作单。20 条制作单在结构化模板方案下不需要视觉模型调用，OpenAI 生成 token 可为零；若批量调用文本模型，按每条约 500–1,500 输入 token、200–500 输出 token的预算，20 条合计约 10,000–30,000 输入 token、4,000–10,000 输出 token。按 GPT-6 Luna 当前标准输入 $0.10/百万 token、输出 $0.50/百万 token估算，约 **$0.003–$0.008**，预算可按每 20 条 **$0.01 以内**预留。实际提示长度和模型价格变化会影响用量。

首版增加**一张风格校准图**作为生成流程的确认节点：从已锁定日历中选一条有代表性的内容先生成，客户确认整组视觉方向后，再继续生成其余内容。校准图尽量计入 20 条交付中的第一条；客户可要求**一次风格调整并重生成**，这次重生成计入校准流程的预算。校准通过后，后续内容沿用已确认的视觉方向；额外图片生成按实际次数计入成本。客户确认的是视觉风格，不需逐条检查其余图片提示词。图片生成费按第十节图像估算另计，不包含在上述制作单文本 token 费用中。

校准通过后，每条内容默认先生成一张成品图，而不是每条都先抽多个候选供客户挑选。系统按制作单逐条生成，再做内部质量检查。质检至少检查画幅、主体和产品参考一致性、未经确认的信息、重复构图及示意图免责声明。**发现明确制作错误时自动重做一次；第二次仍未通过，暂停该条并通知管理员处理，不继续自动抽图。**客户偏好修改属于交付后的反馈，不混入自动质检重试。成本估算中的“3 个候选 + 2 轮修改”只是预算情景，不是已定生产规则。

### 8.2 成品批量审核与修改

整组内容通过内部质检后，在同一个客户专属链接页面按营销日历顺序展示，客户一次查看并整体确认。客户可整体通过，或提交一份集中修改意见；指出具体哪几项是可选的反馈方式，不要求逐条审批。凡使用 AI 示意内容的项目应在页面中明确标记。

客户偏好变化提供**一轮整组集中修改**，修改后客户再整体确认并锁定成品。制作或事实错误（例如商品不符合已确认素材、出现未经确认的价格/事实、免责声明缺失）由 PoStory 修正，不占客户偏好修改轮次。日历锁定/成品确认后新增商品、改变主题或范围的处理方式，由管理员评估对进度和费用的影响；具体收费规则待定。

### 8.3 成品确认后的社媒授权与自动排期

PoStory 现有 Ayrshare 社媒授权和发布连接已实现。客户整体确认最终成品后，主流程立即引导其授权希望发布内容的社交平台账号，避免把“看过/下载成品”误认为营销流程已经完成。社媒授权是独立、明确的授权动作；成品审核通过本身不代表已取得发布权限。

授权成功后，客户只需选择**开始发布的日期**。系统按本期 20 条内容及 30 天计划，默认每隔约 1–2 天均匀安排，包含周末；不要求客户逐条设置发布时间。客户可以调整整体安排，指定偏好的发布日或不发布日，例如只安排周二、周三、周四，周末留白。

客户选定的发布日优先于默认频率。如果可发布日期不足以在 30 天内安排完 20 条，系统仍在客户选定的日期内尽量均匀分配，**允许同一天安排多条，并自动错开发布时间**；不把内容挪到客户指定的不发布日，也不擅自减少条数或延长周期。例如客户只选择周二、周三、周四时，周末留白，部分周二至周四会安排多条。系统展示整体日历和摘要；客户不必逐条设定日期。

排期默认使用客户店铺地址所在时区，客户可以修改；同日多条由系统安排为不同时间。PoStory 的排期逻辑负责根据开始日期、允许发布日、数量和时区计算每一条的确切发布时间，并把时间交给 Ayrshare；Ayrshare 负责按指定时间执行发布并返回状态。Ayrshare 支持通过 UTC `scheduleDate` 创建未来发布任务，也提供按预设日期/时间槽位自动安排的 Auto-Schedule；本流程需要遵循客户的个性化星期规则，因此首选由 PoStory 算出各条时间，再用 `scheduleDate` 提交。发布时间的具体算法、同日多条之间的最小间隔仍待讨论。未完成社媒授权时，自动发布保持待设置状态，不能显示为已排期或已发布。

产品主流程应优先完成社媒授权和自动排期，而不是先把客户带到单纯下载成品的页面。若客户拒绝/暂不授权时，是否允许仅下载、如何提醒和是否暂停服务，还需要确定。

发布失败规则：临时故障自动重试有限次数；多次失败后只暂停/移动失败的那条，不擅自改变其他内容的既定时间。若授权失效，暂停后续自动发布并等待客户重新授权；恢复后将失败内容安排到客户允许的下一个发布日，并避开同一时间重复。若 30 天内已没有可用日期，提示客户/管理员选择延长周期或其他处理方式。因平台拒绝、内容问题等需要人工判断的失败，暂停对应内容并通知管理员，不自动改写后再次发布。具体重试次数、间隔、通知渠道和补发期限仍待讨论。

通知原则已确认：所有发布异常都记录并进入管理员后台；**需要处理的异常通过邮件通知管理员，由管理员自行联系客户**，例如社媒授权失效或需要补充资料。系统不直接给客户发送邮件或短信。客户再次打开专属链接时可查看当前状态和需要处理的事项。可以自动恢复、无需人工处理的重试不打扰客户。管理员邮件提醒的严重级别和频率仍待讨论。

若真实素材或已核实信息不足以支撑 20 个不同主题，允许用 AI 生成的**示意内容**补足计划数量。示意内容必须在日历中清楚标注、汇总示意内容数量，并纳入整份日历供客户一次性查看；不要求客户逐条批准示意内容。客户如希望仔细检查，可主动选择逐条查看。示意内容不能伪装成真实商品照片或真实促销。图片需清楚显示免责声明 **“AI 生成示意图｜商品外观以实物为准”**；发布配文也需在图片裁切后无法辨认免责声明时说明。示意图不得补造商品名称、价格、配置、功效、库存或优惠；这些仍须来自客户确认资料。

为提高响应速度并避免每次都让大模型从零编排，采用“通用主题模板 + 行业小幅变化 + 客户资料填充”的方向。模板建议保存常见内容主题、适用目标、素材条件和不可编造的事实字段；系统按行业、季节/活动、已确认商品、客户目标和素材质量挑选并填入。大模型只用于解释不清、特殊活动或模板覆盖不到的少数情况，而不是每个日历项都从空白开始生成。**竞品调研已从流程删除**：不自动搜索同行，日历不声称来自实时市场或竞品调研。

本轮已确认的顺序为：客户上传 → 图片识别或视频主题/商品候选/活动关系整理并检查素材 → 归入该客户本期素材池 → 客户确认制作范围及素材状态 → 客户选择本月主要目标（可选次要目标）→ **系统依据所选目标和行业模板自动安排 20 个内容主题** → 生成 30 天营销日历 → 客户默认整体查看并确认日历（逐条确认是可选细看方式；日历可纳入带免责声明的 AI 示意内容补足 20 个主题）→ 按日历逐条生成高画质图片。客户不负责手动拆分或分配 20 条；各目标对应的系统模板/内容比例仍待设计。

### 8.4 三十天发布后的管理员复盘

30 天发布周期结束后，系统整理本期复盘并**只发送给管理员**；是否转发给客户由管理员决定，系统不直接向客户发送复盘。

复盘按客户当月选定的主要目标**突出一个核心指标**，并列其他平台表现作为辅助；不能用与目标无关的高浏览量代替业务结果。首版目标与核心指标建议如下：

| 本月主要目标 | 复盘核心指标（首版建议） | 说明 |
|---|---|---|
| 让更多本地顾客认识店铺 | 本地触达或播放量 | 具体平台能否提供本地范围数据需实测；否则使用可取得的触达/播放数据并注明范围 |
| 吸引顾客到店 | 地图/路线入口点击；若无则为行动入口点击 | 实际到店情况需客户/管理员补录，不能从浏览量推断 |
| 增加电话或预约 | 电话或预约入口点击 | 实际来电、完成预约需客户/管理员补录 |
| 介绍新品或重点服务 | 收藏/分享或相关咨询 | 以平台可取得数据为准；咨询可人工补录 |
| 宣传本月促销/活动 | 促销入口点击或相关咨询 | 实际成交需有订单/客户记录，不能由互动量推断 |
| 让社交账号持续有内容 | 计划发布完成率 | 触达与互动作为辅助指标 |

如果平台或账号无法提供某项核心数据，报告标注“未取得”并说明可提供的替代数据，不估算、不补造。平台指标的可自动获取范围需要用目标账号实测。

复盘建议分三部分：

1. **执行情况：**计划发布数量、实际发布数量、失败/未发布数量及处理状态。
2. **平台表现：**平台可提供的浏览/触达、互动、收藏/分享、链接点击等数据；按平台来源分别标明，不把不同平台口径混成同一个数字。
3. **客户结果补充：**电话、预约、到店或成交等结果，只有在管理员/客户提供了记录时才呈现；不能仅凭浏览或互动数据声称带来销售。

复盘可结合本月主要目标提出下一期的内容方向建议，但由客户/管理员重新选定下月目标。哪些平台指标能自动取得、复盘发送时间、客户结果怎样录入与验证，仍待后续讨论。

## 九、模型和 ChatGPT 订阅额度的区别

- 视觉理解模型用于识别商品、画面和素材质量；GPT Image 模型用于生成或编辑图片。二者用量分别计算。
- GPT Image 2.6 有 Sunburst（偏细节工作）与 Flare（偏快速生成/调整）。真实商品外观应尽可能保留客户实拍，再用图像合成加入背景、文字、Logo 和免责声明；AI 生成商品外观时按示意图标注。
- ChatGPT 订阅额度与 OpenAI API 账单分开。不能假设个人 ChatGPT 订阅可以直接当作 PoStory 云端的通用后台 API 额度；订阅额度连接只适用于支持的授权方式，并有限制。API 自动化预算应按 API 用量评估，或另行研究自托管模型和机器成本。
- 本文件中的价格是 API 输出估算，不是 ChatGPT 订阅额度，也不含 GCP、存储、视频剪辑、运营或人工成本。

## 十一、拓展构想（待确认）：Before / After 案例内容

客户或代理商提供原始照片/视频，PoStory 生成经过整理、优化或剪辑的成品，形成真实的 Before / After 对比。该形式可以发展成两条分开的内容线：

1. **客户自己的营销内容：**客户原始素材 → PoStory 制作结果 → 客户自己的社交平台图文/视频。
2. **PoStory 自己的获客案例：**取得客户对具体素材和成品的单独许可后，PoStory 生成案例封面、Before / After 对比、制作过程说明和笔记文案，供 PoStory 自己发布（例如小红书）。

PoStory 自有案例可讲清楚原素材的问题、具体做了哪些改变、最终画面和适用场景；不能编造流量、成交或客户评价。若画面是 AI 概念示意而非真实商品外观，继续使用前文确定的免责声明。客户授权是否在交付后逐案征求、是否允许匿名展示、是否包含原视频/图片/店名等，均待讨论；未授权的素材不进入 PoStory 案例库。

经常发布 Before / After 笔记有机会展示服务能力并吸引潜在客户，但不能保证带来流量。可把它作为独立的获客内容试验，之后用浏览、收藏、关注和有效咨询评估效果，不把曝光承诺写进客户交付。

15. 是否将 PoStory 的 Before / After 案例内容作为独立获客流程；何时征求客户许可、匿名选项、案例素材保留期限。

## 十三、实现后验证项（不是流程讨论的前置结论）

- 12 帧初筛 + 最多 6 帧补抽（每段总上限 18 帧）能否覆盖多商品促销、预算挑战和店铺介绍中的重点，由实现后使用代表性真实素材测试；不预设其已经足够。
- 上传文件数量/大小上限、识别用时、实际 token/费用、商品分组准确度和真实商品保真度均以测试记录为准。
- 验证 PoStory 将店铺本地时间转换为 Ayrshare 所需 UTC `scheduleDate` 后，20 条任务是否按开始日、允许发布日和 30 天边界正确创建；检查 Ayrshare 返回状态/回调，并测试失败项只移动自身、不改动其他排期。

## 十四、端到端验收标准（执行清单）

每个阶段都按“输入 → 预期结果 → 通过条件 → 失败处理人”验收。状态区分未实现、未执行、部分通过和失败；只有测试记录、日志或截图支持时才标为通过。

| 阶段 | 输入 | 预期结果与通过条件 | 未通过时由谁处理 | 状态 |
|---|---|---|---|---|
| 1. 专属链接与资料提交 | 分别创建 PoStory/代理商链接；提交完整、缺项、归属矛盾的资料 | 无登录提交；品牌和代理归属正确；缺项退回补充；矛盾资料暂停自动处理并进入管理员队列；客户之间数据隔离 | 系统暂停；管理员核实并联系客户 | 未实现/未执行 |
| 2. 付款/线下结算闸门 | 同一项目分别设为未付款、已付款、已登记线下结算 | 未满足付款条件不启动 AI 识别/生成；满足后才进入制作 | 管理员处理付款状态或订单异常 | 未实现/未执行 |
| 3. 上传与识别 | 代表性图片、店面/货架图、多商品视频；分别测试文件有效、超限、重复、模糊 | 文件限制和错误提示正确；异步状态能完成或给出失败状态；客户界面不显示来源图片/时间点/AI 建议名称或特征；视频输出主题、重点商品候选和活动关系；资料不足则明确标待核实 | 识别失败交管理员；需商品事实时管理员联系客户补资料 | **部分通过（内部 MVP）：**管理员测试台已真实处理两段视频并覆盖主题、转写、候选及关系输出；访问控制通过。客户上传流程/异步进度未实现，通用图片限制仍是 15 MB；商品候选仍有重复/错分，不能视为识别准确度验收通过 |

### 视频识别 MVP 开发与实测（2026-11-08）

- **测试台：**新增管理员专用 `/admin/video-lab` 和 `/api/admin/video-recognition`。必须显式设置 `ENABLE_VIDEO_LAB=true` 才可访问；默认关闭。结果不保存进数据库；视频、抽取画面及临时音频在请求临时目录处理并清理。此入口不是客户上传流程，也没有接入正式制作或发布。
- **处理方式：**本机 FFmpeg/FFprobe 校验视频；每段最多 180 秒、250 MB；均匀取 12 帧初筛，按场景切换在样本间隔补抽最多 6 帧；抽取口播后用 `gpt-transcribe`，画面用 `gpt-6-luna` Responses API + Structured Outputs。画面数、时间、token 和费用只在管理员测试结果显示；客户专属页面仍未实现。
- **素材结果：**《500刀家具预算挑战》78.7 秒，检测 30 个场景切换，识别 18 帧，运行约 16.3 秒；识别主题为预算挑战，并抽出圆桌、按摩椅等候选及预算/促销关系。《黑五冰箱洗衣机烘干机促销》42.9 秒，检测 11 个场景切换，识别 15 帧，运行约 12.7 秒；识别出黑五促销主题、冰箱候选和洗衣机/烘干机组合关系。金额币种未明确时，结果标记币种未确认，没有换算成美元。
- **费用记录：**最终版两段单次识别共 25,612 个视觉模型输入 token、2,899 个输出 token；按官方模型价及口播模型的音频时长单价估算合计约 **US$0.0131**（家具视频约 $0.00805，家电视频约 $0.00508）。这是本次实际用量折算值，不是未来每段视频的固定价格。为修正提示词并复跑验证，迭代期间三轮两段视频共约 **US$0.0386**。
- **质量判断：**大主题、口播辅助、促销/组合关系和事实待核实状态可以跑通；产品级去重仍有模糊组/重复候选，单帧商品也可能无法与口播准确对应。因此两条视频是 MVP 冒烟测试，未证明识别准确率。客户单品内容继续要求客户提供的商品名单、菜单或价目表。
- **访问测试：**隔离测试库中管理员可进入测试台；未登录请求返回 401，普通账号调用识别接口返回 403。测试未访问正式数据库、正式社媒账号或线上 PoStory 服务。
- **代码检查：**修改文件的 TypeScript 检查、ESLint 和 `npm run build` 通过。全仓 `check-i18n` 仍被其他页面残留中文和既有空文案挡住；本次新增中英文 key 数量一致。
- **当前限制：**测试需要本机安装 FFmpeg/FFprobe 以及已配置的 OpenAI API key。容器/Cloud Run 未验证；上线前要核对目标环境的请求限制，并考虑对象存储直传和后台异步处理。不得在客户入口开启该内部测试台。
